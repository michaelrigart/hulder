# Hulder v1 Implementation Plan

**Status:** In progress (branch `feat/hulder-v1`). Codex approved the plan in round 4.
**Amended:** 2026-11-01, after Task 2's findings: Task 10a added; Tasks 11–13 and 17
revised.
**Amended:** 2026-11-02, after the pre-merge review stopped converging: Task 16a added;

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Hulder. It is a macOS 27 menu bar manager that hides other apps' menu bar
items per app in three sections and reorders them around its own icon. It survives
crashes, and its macOS 27 specifics are isolated so that a later macOS touches one layer.

**Architecture:**
- **`Packages/HulderCore`** holds the rules: the model, the reveal state machine, the
  concealment and order planners, and the two controllers that own assertions and order
  writes. It also declares the platform interface. It imports Foundation and Observation
  only.
- **`Packages/HulderPlatform27`** implements that interface for macOS 27. It holds every
  private symbol and every `#available` check.
- **The app target, `Hulder`,** is a thin AppKit and SwiftUI shell. Its composition root
  wires the parts together.

**Tech Stack:**
- Swift 6.4 (Xcode 27.2, macOS 27.2 SDK) and Swift Testing.
- AppKit `NSStatusItem`, SwiftUI in `NSHostingView` windows.
- Accessibility (`AXUIElement`), the private `MenuBarClientCore.framework` loaded at run
  time, Carbon `RegisterEventHotKey`, ServiceManagement (`SMAppService`) and `os.Logger`.
- XcodeGen, pinned in `mise.toml`.

**Spec:** `docs/superpowers/specs/2026-10-31-hulder-design.md`. Read it before any task.
"What macOS 27 allows" and "Measured on macOS 27.2" hold every platform fact this plan
relies on; where they differ, the measured section holds.

## Global Constraints

- **Platform and language:**
  - Deployment target macOS 27.0, Swift 6 language mode, complete strict concurrency
    checking.
  - Packages use `// swift-tools-version: 6.4` and `.macOS(.v27)`; if `.v27` is not
    defined, use `.macOS("27.0")`.
- **Bundle and signing:**
  - Bundle identifier `com.michaelrigart.hulder`.
  - Info.plist: `LSUIElement` YES, `CFBundleDisplayName` Hulder, version `0.1.0`, build
    `1`.
  - Not sandboxed (no `com.apple.security.app-sandbox`). Hardened Runtime on.
  - Ad-hoc signing (`CODE_SIGN_IDENTITY "-"`, `CODE_SIGN_STYLE Manual`).
- **Core imports:** `HulderCore` imports only `Foundation` and `Observation`. No AppKit,
  SwiftUI, ApplicationServices or `os`, and no `#available`.
- **Platform code:**
  - Private API and `#available` checks live only in `Packages/HulderPlatform27`.
  - Every private symbol is resolved at run time. A missing one becomes
    `Availability.unavailable(reason)`, never a crash.
- **Never:**
  - post synthetic mouse or keyboard events;
  - write any system file except the order file, under the spec's "Order" rules;
  - touch Control Center's preferences;
  - make network calls or collect telemetry;
  - ask for Full Disk Access.

  The only permissions are Accessibility and access to the order file, picked by the user.
- **Values:**
  - assertion activation timeout 3 s;
  - order confirmation timeout 3 s;
  - Accessibility messaging timeout 0.25 s per element;
  - at most 4 Accessibility reads at once;
  - system-item policy on 27 is `Array(0...127)`.
- **Settings defaults:**
  - rehide delay choices 5, 10, 30 and 60 s, plus never; the default is 10 s;
  - default section for new apps: Visible;
  - launch at login on;
  - hotkeys unset.
- **Files** live in `~/Library/Application Support/com.michaelrigart.hulder/`:
  - `state.json` (version 1);
  - order backups in `OrderBackups/`, keeping the newest 10.
- **Coordination:**
  - No `Task.sleep`, `asyncAfter` or timers to let things settle. Sleeps happen only on
    an injected `Clock`, for the rehide delay and the timeouts above.
  - Blocking Accessibility or private calls run on dedicated `DispatchQueue`s, never on
    the main actor or the cooperative pool.
- **Unsafe annotations.** `@unchecked Sendable` and `nonisolated(unsafe)` each need a
  `// reason:` comment on the same line.
- **Fixed text.** Every `Availability` reason and every user-facing failure text is a
  fixed string written by Hulder. Failures are `FailureKind` values (Task 10).
  - A system error description is never put into an outcome, a reason or a report.
  - The platform code that catches such an error logs it at `.private` privacy, then
    throws or returns the fixed kind.
- **Logging:**
  - `Logger(subsystem: "com.michaelrigart.hulder", category: …)`.
  - State changes and failures at `.notice`. Bundle identifiers may be `.public`; no other
    personal data.
- **Build and test outside the Claude sandbox.** Prefix every Swift or Xcode command with
  `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`. Don't change
  `xcode-select`.
- **Parallel tasks** pass their own build paths so concurrent builds don't fight over a
  lock:
  - `--scratch-path build/spm-task<N>` for `swift test`;
  - `-derivedDataPath build/dd-task<N>` for `xcodebuild`.
- **Generated, never committed:** `Hulder.xcodeproj/`, `build/` and `.build/`.
- **Clean room.** Never open Thaw's or holzBar's source. Facts come only from the spec,
  Apple's SDK, run-time inspection and Hulder's own probe.
- **Copy:** English only. Public docs and commits carry no machine details beyond the
  spec's.

## Review Focus

1. **Hulder's own icon is missing from the bar,** because macOS dropped it or it sits under
   the notch. Reordering actions answer "Hulder's icon isn't on the menu bar" and change
   nothing; hiding is unaffected. Tested in Tasks 7 and 10.
2. **Accessibility is revoked while Hulder runs.** Hiding keeps following the layout and the
   running apps. Inventory keeps the last known items, marked stale. Settings shows the
   missing permission. Tested in Tasks 9 and 16a; the Settings state is checked in Task 16,
   Step 3.
3. **Items owned by agent or helper apps** (accessory or prohibited activation policy, or
   a helper bundle different from the main app) count as running apps and are
   allowlisted. Tested in Task 11.
4. **Two items of one app with identical Accessibility attributes** get distinct keys, the
   same ones on every scan. Tested in Task 12.
5. **A corrupt `state.json`** is moved aside as `state.corrupt.json`, Hulder starts fresh
   and says so, and the bad file is never silently overwritten. Tested in Task 3.
6. **A process whose menus Hulder can't watch draws an item:** its observer fails, or
   misses one of the four notifications. Menu tracking is partial while its item is drawn,
   so automatic hiding is off and Settings says why. It comes back once the item is gone. A
   background-only helper, or a process macOS doesn't list as an app, is attached like any
   other drawn owner, and its menus count like any other app's. While a newly drawn
   process's observer is still being set up, tracking is partial. Tested in Task 16a.
7. **An app Hulder has seen quits and relaunches while hidden.** Layout shows the items it
   last drew, marked stale, and its order entries add none. Tested in Task 16a.
8. **New apps appear before the order file has answered** (every launch). They stay new
   until a scan can place them, then are placed once, in one write, also if they were hidden
   meanwhile. Without reordering they are recorded and never placed. Tested in Task 16a.

**Depends on:** Task 1 · **Tier:** sp-mechanical

**Interfaces (Produces):**
- **`AppID`:** `public struct AppID: Hashable, Comparable, Codable, Sendable` with
  `let bundleID: String` and `init(_ bundleID: String)`. It is coded as a single string.
- **`Section`:** `public enum Section: String, Codable, Sendable, CaseIterable` with cases
  `visible`, `hidden` and `alwaysHidden`.
- **`ItemKey`:** `public struct ItemKey: Hashable, Codable, Sendable` with
  `let raw: String`. It is opaque; the platform builds it.
- **`ItemOwner`:** `public enum ItemOwner: Hashable, Sendable` with:
  - `case app(AppID, name: String)` and `case unresolved(processName: String)`;
  - `var id: String`, which is the bundle identifier, or `"process:" + processName`;
  - `var appID: AppID?`.
- **`MenuBarItem`:** `public struct MenuBarItem: Hashable, Sendable` with:
  - `key: ItemKey` and `owner: ItemOwner`;
  - `description: String?` and `title: String?`;
  - `isManagedByMacOS: Bool`;
  - `barPosition: Double?`: the item's left edge on the bar, or nil when it isn't drawn.
    It gives the bar order across owners when the order file isn't available.
- **`Layout`:** `public struct Layout: Codable, Equatable, Sendable` with:
  - `var defaultSection: Section = .visible` and `private(set) var apps: [AppID: KnownApp]`;
  - `func section(of: AppID) -> Section?`;
  - `mutating func assign(_: AppID, to: Section)`;
  - `mutating func recordSighting(_: AppID, name: String, at: Date) -> Bool`, which
    returns true on a first sighting and assigns `defaultSection`; later calls update only
    the name and the date;
  - `mutating func forget(_: AppID)`;
  - `func effectiveSection(of: AppID) -> Section`, which is `section(of:) ?? defaultSection`.
- **`KnownApp`:** `public struct KnownApp: Codable, Equatable, Sendable` with `section`,
  `name` and `lastSeen: Date`.
- **Settings:**
  - `public enum RehideDelay: String, Codable, CaseIterable, Sendable` with cases
    `seconds5`, `seconds10`, `seconds30`, `seconds60` and `never`, and
    `var duration: Duration?`.
  - `public struct Hotkey: Codable, Equatable, Sendable` with `keyCode: UInt32` and
    `modifiers: UInt32`.
  - `public struct HulderSettings: Codable, Equatable, Sendable` with
    `launchAtLogin = true`, `rehideDelay = .seconds10`, `toggleHotkey: Hotkey? = nil` and
    `revealAllHotkey: Hotkey? = nil`.
- **State:**
  - `public struct HulderState: Codable, Equatable, Sendable` with `layout` and
    `settings`.
  - `public enum StateCodec` with `static let currentVersion = 1`,
    `static func encode(_: HulderState) throws -> Data` and
    `static func decode(_: Data) throws -> HulderState`.
  - The encoding is pretty-printed JSON with sorted keys and ISO 8601 dates:
    `{"version":1,"layout":…,"settings":…}`.
  - `public enum StateFileError: Error, Equatable` with `unsupportedVersion(Int)` and
    `corrupt`.
- **`StateStore`:** `public final class StateStore: Sendable`, with
  `init(fileURL: URL)`:
  - **`func load() -> StateLoad`** returns `.fresh`, `.loaded(HulderState)`,
    `.recoveredFromCorrupt` or `.refused(StateFileError)`. A corrupt file is moved to
    `state.corrupt.json` next to it.
  - **`func save(_: HulderState) throws`:**
    - it writes atomically and creates the directory;
    - it throws `StateFileError.unsupportedVersion(n)` without touching the file whenever
      the file on disk has an unsupported version.

### Task 6: Concealment controller: assertion ownership

**Depends on:** Tasks 4 and 5 · **Tier:** sp-standard

**Files:**
- Create: `Packages/HulderCore/Sources/HulderCore/Concealment/ConcealmentController.swift`
- Test: `Packages/HulderCore/Tests/HulderCoreTests/ConcealmentControllerTests.swift`,

**Interfaces (Produces):**
- **Types:**
  - `public struct ConcealmentToken: Hashable, Sendable` with `let id: UInt64`.
  - `public enum ConcealmentFailure: Error, Equatable, Sendable` with cases
    `unavailable(String)` (fixed text), `rejected` and `timedOut`.
  - `public enum ApplyOutcome: Equatable, Sendable` with cases `applied`, `unchanged`,
    `superseded` and `failed(ConcealmentFailure)`.
- **The backend protocol:** `public protocol ConcealmentBackend: Sendable` with:
  - `func prepare(_: AllowList) async throws -> ConcealmentToken`, which creates the
    assertion object;
  - `func activate(_: ConcealmentToken) async throws`, which returns when MenuBarAgent
    confirms;
  - `func invalidate(_: ConcealmentToken) async`, which is idempotent.
- **The controller:** `public actor ConcealmentController`:
  - `init(backend: any ConcealmentBackend, clock: any Clock<Duration>, timeout: Duration = .seconds(3))`;
  - `func apply(_: Concealment) async -> ApplyOutcome`;
  - `func releaseAll() async`;
  - `var current: Concealment`.

**Algorithm** (spec, "Apply a concealment"):
1. **Queueing.** Requests are processed one at a time, in arrival order. When a request
   starts and a newer one is already queued, it returns `.superseded` without calling
   the backend.
2. **Unchanged.** If the request equals `current`, return `.unchanged`.
3. **`.none`.** Invalidate the live token, set `current = .none`, and return `.applied`.
4. **`.allow(list)`:**
   1. `prepare` the list, then race `activate(token)` against `clock.sleep(for: timeout)`.
   2. **Activation wins:**
      - if a newer request is queued, invalidate the token and return `.superseded`;
      - otherwise invalidate the previous live token, keep the new one, set `current`, and
        return `.applied`.
   3. **Activation throws:** invalidate the token and return
      `.failed(.rejected)`. The backend has already logged the system description privately. The
      previous assertion stays.
   4. **The timeout wins:** invalidate the token at once and return `.failed(.timedOut)`.
      Keep a detached task that calls `invalidate(token)` again if activation completes
      later.
5. **`releaseAll()`** closes the controller. It is used only at quit.
   - It invalidates the live token and every prepared token that hasn't finished, and sets
     `current = .none`.
   - Queued requests, and every later `apply`, return `.superseded` without calling the
     backend.
   - An activation that completes after the release is invalidated at once and never
     becomes current.

**Depends on:** Tasks 4 and 7 · **Tier:** sp-standard

**Files:**

**Interfaces (Produces):**
- **The store protocol:** `public protocol OrderStore: Sendable` with:
  - `func read() async throws -> BarOrder`;
  - `func backup() async throws`;
  - `func write(_: OrderChange, expecting base: BarOrder) async throws`;
  - `func latestBackupOrder() async throws -> BarOrder`;
  - `func restoreLatestBackup() async throws`;
  - `func changes() -> AsyncStream<BarOrder>`: the persisted order. It emits the current
    value first, then again whenever the file changes;
  - `func displayed() -> AsyncStream<[ItemKey]>`: the left-to-right order of the items
    MenuBarAgent is actually drawing. It emits the current value first, then again on every
    observed change to the bar.

  `write` must throw `OrderStoreError.stale` when the order on disk isn't `base`. The
  platform's write mechanism guarantees that a concurrent MenuBarAgent update is never
  lost. A persisted order doesn't count as applied until `displayed()` shows it.
- **Errors:** `public enum OrderStoreError: Error, Equatable, Sendable` with cases `stale`,
  `unsupportedFormat(String)` (fixed text), `noAccess` and `io`.
- **Outcomes:** `public enum OrderOutcome: Equatable, Sendable` with cases `applied`,
  `saved`, `unchanged`, `unconfirmed`, `gaveUp`, `unavailable(String)` and `failed`.
  `saved` means persisted, but not visible on the bar, because none of the moved items is
  drawn.
- **The controller:** `public actor OrderController`:
  - `init(store: any OrderStore, clock: any Clock<Duration>, confirmTimeout: Duration = .seconds(3))`;
  - `func perform(_ plan: @Sendable (BarOrder) -> OrderChange?) async -> OrderOutcome`;
  - `func restore() async -> OrderOutcome`.

**Algorithm:**
1. **Queueing.** Operations run one at a time.
2. **`perform`:**
   1. `read`, then `plan`. A nil plan returns `.unchanged`.
   2. Subscribe to `displayed()` and `changes()`, then `backup`, then
      `write(change, expecting: read order)`.
   3. **On `.stale`,** read, plan, back up and write once more. A second `.stale` returns
      `.gaveUp`.
   4. **Confirming.** Wait up to `confirmTimeout` for evidence of the move.
      - **What counts as evidence.** The first element of each stream is the state from
        before the write, so it never counts. Every later element counts, including one
        emitted during the `write` call itself.
      - **Drawn items.** Let `drawn` be the moved keys that appear in a `displayed()`
        element `d`. If `drawn` isn't empty, `d` confirms when it equals `change.target`
        filtered to the keys in `d`.
      - **Nothing drawn.** If none of the moved keys is drawn (they are hidden, or `d` is
        empty), the drawn bar can't show the move.
        - A `changes()` element equal to `change.target` returns `.saved`, never
          `.applied` (spec, "Confirming").
        - Hulder never reveals items to check.
      - **No evidence** by the timeout returns `.unconfirmed`.
3. **Errors.** `.unsupportedFormat(r)` and `.noAccess` from any call return
   `.unavailable(r)` or `.unavailable("No access to the order file")`, without writing.
   `.io` returns `.failed`. The platform has already logged its description privately.
4. **`restore`:**
   1. Capture the expected target with `latestBackupOrder()`.
   2. Subscribe to both streams, then run `restoreLatestBackup()`.
   3. Confirm against the captured target with the same evidence rules. Every key whose
      position differs between the current order and the target counts as moved.

   The comparison is always with the captured target, never with a re-read.

      - **Spacing.** Each run of consecutive moved keys in `change.target` sits between its
        nearest unmoved neighbours, with values `vR + (vL − vR) · (m − j) / (m + 1)` for
        `j` in `0..<m`. Here `vL` is the left neighbour's value, `vR` the right one's, and

      - **No right neighbour:** `vR` is 0. With neither neighbour, the left-end rule then
        gives `20 · (m − j)`.

        Otherwise `applying` throws `OrderStoreError.unrepresentable` (Task 10a), and
        nothing is written. Examples: equal neighbour values, rounding between adjacent
        values, or a left neighbour at or below 0 with no right neighbour.

    container URL and the backups folder:
    - **Its state.** A `Mutex` guards the cached current order and the subscribers.
    - **One queue.** Every `PositionsBackend` call runs on one serial `DispatchQueue`.
      Reads therefore reach the cache and the subscribers in the order they were made.
    - **`read()`** decodes `copyPositions()`.
    - **`backup()`** copies `Library/Preferences/com.apple.MenuBar.plist` to
      `OrderBackups/<ISO8601>.plist`, then prunes all but the newest 10.
    - **`write(_:expecting:)`:**
      1. calls `copyPositions()` and decodes it immediately before writing;
      2. throws `.stale` if that isn't `base`;
      3. otherwise sets the result of `applying`;
      4. throws `.io` if `setPositions` returns false;
      5. re-reads through `copyPositions()` and broadcasts the result, as the watcher
         does.

      All five run in one block on the serial queue, so nothing runs between the copy and
      the set.
    - **`restoreLatestBackup()`** sets the newest backup's positions, then re-reads and
      broadcasts in the same block.
    - **`latestBackupOrder()`** decodes the newest backup.
    - **`changes()`** is synchronous. Under the `Mutex` it yields the cached order and
      registers the subscriber in one step. A subscriber made before `write` is called
      therefore gets its first element from before the write, and the write's own
      broadcast after it, whether or not a file event arrives.
    - **The watcher.** A `DispatchSource` file-system object on the container's
      `Library/Preferences` directory (write, rename, delete, extend, attrib) is installed
      when the store is created, before `orderStore()` returns it. On each event it
      re-reads on the serial queue and broadcasts.
    - **`drawnKeys()`** runs `MenuBarAgentReader.read` once and maps the groups to keys
      with `ItemKeyBuilder`. On failure it returns an empty set.
  - **`OrderAccess27`:**
    - **Grant.** `grant(pickedURL:)` accepts only a folder named `com.apple.MenuBar`
      whose positions decode. It stores a `.withSecurityScope` bookmark in
      `UserDefaults` under `OrderContainerBookmark`.
    - **Scope.** It keeps `startAccessingSecurityScopedResource()` active while Hulder
      runs.
    - **Stale bookmarks.** It re-creates a stale bookmark from the resolved URL.
    - `suggestedLocation` is `~/Library/Group Containers/com.apple.MenuBar`.
  - **`Platform27`:**
    - **The store.** `orderStore()` returns an `OrderStore27` when access is granted,

    - **Capability.** `reordering` follows the same conditions, with the reason when it's
      unavailable. `grant` makes it emit again.

### Task 16a: Consolidate inventory memory, first sightings and process coverage

**Depends on:** Tasks 12–16, as the pre-merge fixes left them (05307cd) · **Tier:** sp-standard;
its task review runs on sp-architect

Three pre-merge review rounds kept finding bugs in the previous round's fixes, always in the
same three places (ledger: "Codex pre-merge round 1/2/3", rulings R54–R62). Each place had
two memories with different lifetimes, or two process sets that disagreed. This task gives
each rule one owner, and builds in Michael's decision of 2026-11-02 (spec, Decisions).
Design note: `.superpowers/sdd/2026-10-31-hulder-v1/task-16a-design.md`.

- **Inventory.** The platform reports only what a pass found. `InventoryMemory`, in the core,
  remembers for the whole run the items each owner was last seen drawing, and builds the
  inventory from that memory and the pass. The scanner's `previousOwners` and
  `observedDrawn`, and `InventoryMerger`, go.
- **First sightings.** There is no queue. A pass records a new app only when it can also
  place it: the pass read the order file and a controller is installed. When reordering is
  known to be unavailable, it records without placing. Otherwise the app stays new, and the
  next pass sees it again, also while the app is hidden: staleness keeps a known app's name
  and day from changing, never a new app from being recorded. `SightingPlacementGate` goes.
- **Coverage.** A process that draws an item stays covered until a scan stops finding its
  item, whatever macOS's list of running apps says. The tracker keeps one watched set, the
  trackable apps and every covered process, whatever its activation policy and whether
  macOS lists it as an app (ruling R63). That one set decides what is attached, whose events
  and windows are read, and whose open menus are forgotten. Tracking is full only when every
  covered process is attached, which means all four notifications registered (R61(4)); an
  attach still in flight doesn't count, and the capability is published on every change. A
  covered process whose attach fails makes tracking partial (Decision A). Whether a
  background-only helper's menus are seen is checked live in Step 12.

- **Produces (core, `Engine/InventoryMemory.swift`):**
  `public struct InventoryMemory: Equatable, Sendable` with `public init()` and
  `public mutating func apply(_ pass: ScanPass) -> InventorySnapshot`. It holds the last
  snapshot and, per owner id, the items that owner was last seen drawing together with
  whether that pass read the order file (`keyedFromOrderFile`). The rules, in order:
  1. **Unread bar** (`drawn == nil`): the previous snapshot stays as it is, and every owner
     in it, or already stale, is stale. Nothing is remembered or forgotten.
  2. **Drawn owners:** their items as drawn, not stale. They replace what was remembered of
     that owner, and its `keyedFromOrderFile` becomes the pass's `orderEntriesAvailable`.
  3. **Concealed owners** (an owner also in `drawn` is drawn), the first case that applies:
     - **remembered, `keyedFromOrderFile`:** the remembered items, each with `barPosition`
       nil and its `orderKeyIsCertain` kept. The owner is stale. The pass's entry items are
       ignored: what Hulder saw beats a stale entry (R61(5)).
     - **with entry items:** those items, not stale. This covers an app never seen drawn,
       and one seen only before the order file was read, whose remembered keys were made up;
       the order file's keys replace them.
     - **remembered:** the remembered items, `barPosition` nil, certainty kept, stale. The
       pass has no entry for the app, so these are the keys Hulder would make anyway (R58:
       nothing vanishes without order access).
     - **otherwise:** no items, and the owner is stale.
  4. **Every other owner** is left out of the snapshot. What was remembered of it stays for
     the run, so an app that quits and comes back hidden still has it.
  5. **Item order:** drawn owners in the pass's order, then concealed owners in the pass's
     order.
